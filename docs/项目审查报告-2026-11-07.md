## 一、项目是什么

QuillForge 是一个 **AI 驱动的互动叙事（视觉小说/Galgame）生成引擎**，FastAPI 后端（端口 8050）+ 纯前端 HTML 页面，面向"一句话或一个剧本文件夹 → 可玩的互动故事"。

四条产品线：

| 模式 | 入口 | 说明 |
|------|------|------|
| 上传剧本模式 | `/api/start` → `/generate` → `/choose` | 解析 YAML 剧本包（扁平 4 文件 / 嵌套 11 文件），走 Harness 五阶段流水线逐场景生成 |
| AI 实时生成模式 | `/api/realtime/start` → `/choose` | 一句话描述（≤150 字）→ 故事种子 + 场景流式生成，边写边玩 |
| AI 剧本生成 | `/api/generate-script` | 一句话 → 完整剧本包（10+ YAML/MD 文件，SSE 进度） |
| 一键运行 | `/api/auto-run` `/api/auto-run/stream` | 加载剧本文件夹并自动跑全部场景（测试/批量用） |

配套能力：
- **生图**：角色立绘（绿幕→rembg 去背景）+ 场景背景，磁盘缓存（文件名含 model/size/prompt 哈希），OpenAI 兼容协议
- **TTS**：MiMo 音色克隆（有参考音频）→ 预置音色（按性别/年龄自动选择）回退，磁盘缓存
- **前端**：`/`（index.html，VN 主界面）、`/game`（game.html，互动剧场）、`/play`（web_play.html，轻量版）
- **质量门控**：8 项验证（schema/对话轮数/角色一致性/连续发言/性格匹配/主线符合/选项多样性/选项有效性），critical/high 失败触发重试（最多 2 次），对话不足有三层保底

## 二、架构现状

```
routes/（26 端点，只做请求解析/调用引擎/格式化）
  ├─ 上传模式 → quillforge/core.py（薄编排器）
  │     Fixture → Stage1 上下文 → Stage2 旁白 → Stage3 对话(附带选项)
  │     → Stage4 选项(剧本预设优先) → Stage5 验证 → 失败重试/Fallback
  │     LLM 调用全部经 NarrativeSUT；observer 解耦日志/SSE/指标
  ├─ 实时模式 → realtime_engine.py（RealtimeStorySession）
  │     种子流式解析 → characters 数组闭合即提交立绘生成
  │     场景流式解析 → image_description 写完即提交背景生成
  │     选项分支后台预生成（3 线程）+ TTS/生图独立池（10 线程）
  ├─ adapter/（YAML 解析 + 角色字段归一化，不调用 LLM）
  └─ image_gen.py / tts_gen.py（磁盘缓存 + 全局串行生图锁）
```

关键实现事实（审查时实测）：
- 生图 API 调用**全局串行**（`_img_call_lock`）：智谱免费档 cogview-3-flash 同一时刻只允许 1 张在飞，并发即 429；`IMAGE_CONCURRENCY` 只决定排队线程数，`IMAGE_STAGGER_SEC` 控制相邻调用最小间隔
- 生图缓存键 = md5(model|size|prompt)[:8]，prompt 变一个字就重新生成；实时模式与素材页的背景 prompt 字段已对齐（name/location/atmosphere/image_description）
- 同一素材排队期间会被重复提交时，锁内复查磁盘直接复用，不重复调 API
- 静态资源路由有路径穿越防护（resolve + parents 校验）
- 架构约束检查 `scripts/check_architecture.py` 3 项全过（adapter 不调 LLM / routes 不直连 LLM / 文件头完整）
- `.env` 已被 .gitignore 覆盖，不会被提交

## 五、修改建议（按优先级）

### P0 — 版本控制卫生
1. **提交当前 26 个文件的修改**（+978/-491，含实时早生图、并发去重、LLM 加固等），避免工作丢失。.env 已被 gitignore，安全。

### P1 — 文档对齐（按第四节清单逐条改）
3. 版本号统一：建议加 `src/version.py` 或直接用 config yaml 的 version，server.py / README / API 文档 / AGENTS.md 引用同一来源。
4. quillforge.md 重写为 6.x 技术规格（或标注范围）。
5. .env.example 更新为当前验证过的配置（智谱免费档 + 串行化说明 + IMAGE_STAGGER_SEC + IMAGE_REMOVE_BG）。

### P2 — 体验与代码
6. **实时素材页阶段拆分**：首场景背景 + 出场角色立绘优先完成即可进游戏，其余素材后台补（上传模式已有 IMAGE_BG_PRELOAD_COUNT 机制，实时模式 assets-stream 目前等全部完成）。可再缩短跳转等待约 10-20s。
7. **生图并发上限做成配置**（如 `IMAGE_API_MAX_INFLIGHT`）：当前全局串行锁是为智谱免费档硬编码的，换付费服务商后应能放开。
8. 实时模式与上传模式的 assets-stream 生图逻辑有重复，可抽公共函数（低优先级，注意 prompt 字段必须保持一致否则缓存失效）。
9. **实时剧本保存位置**：`save_to_yaml` 直接写入 `samples/<标题>`（realtime_engine.py:1475），生成的故事与内置示例混在一起并被 `/api/samples` 列出（可重玩，应是有意设计），副作用是 git 工作区被测试产物污染。建议二选一：生成剧本移到独立目录（如 `generated_scripts/`，list_samples 同时扫描），或在 .gitignore 中忽略非内置示例。

### P3 — 运维注意
9. `logPrompts/logResponses: true` 会记录完整 prompt/响应，长期运行注意日志磁盘增长（当前 server.log 由 launchd 管理）。
10. `/api/load-folder` 接受任意本地路径——本地工具可接受；若将来暴露公网，需加根目录白名单。
11. 前端三个 HTML 均为单文件大页面，后续如频繁改动可考虑拆 JS（不急）。

### 质量观察（非阻塞，供 prompt 调优参考）

1. **角色命名同质化**：3 轮实时故事都出现了"老周"，2 轮出现"小满"——LLM 命名偏好明显，可在种子 prompt 中要求"避免使用老周/小满等高频名"或引入命名风格约束。
2. **动作旁白偏密**：实时 prompt 要求"约每 2-4 句对话穿插 1 条"，实测 12 对话配 8 动作、16 对话配 9 动作，密度略高于要求，演出节奏偏碎。
3. **Harness 连续发言**：索尔维场景 1 触发 medium 级 consecutive_speaker，可在 dialogue prompt 中再强化"同一角色不得连续 3 轮"。
4. 旁白字数全部落在 150-250 要求区间；对话轮数实时 11-16（要求 10-20）、Harness 11-15（要求 3-15），均合规。
