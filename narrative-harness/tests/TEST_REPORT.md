## 六、剧本结构分类说明

测试剧本分为两种结构类型：

| 类型 | 文件数 | 剧本 | 特点 |
|------|--------|------|------|
| 简单结构 | 4 文件 | 回魂公寓/星河入梦/都市传说 | 元数据+角色+主线+场景 |
| 完整结构 | 11 文件 | 霓虹深渊/回响DEMO | 额外含世界线/事件/结局/角色关系/世界书 |

简单结构剧本不具备：
- 世界线（world_lines）、事件清单（events）、结局系统（endings）
- 角色关系网络（character_relationships）、世界书（worldbook）
- 角色扩展字段（motivation/secrets/relationships/appearance/arc）

系统对两种结构均能正确处理：有数据时注入 prompt，无数据时对应段落自动省略。

## 七、验证器检查项

每次 Pipeline 输出经过 8 项独立检查：

| # | 检查项 | 严重级别 | 说明 |
|---|--------|---------|------|
| 1 | `schema_compliance` | Critical | 旁白/对话/选择结构完整性 |
| 2 | `dialogue_count` | High | 对话轮数在 [3, 6] 范围内 |
| 3 | `character_consistency` | Critical | 所有 speaker 在角色卡中 |
| 4 | `consecutive_speaker` | Medium | 无连续 3 轮以上同一角色发言 |
| 5 | `personality_match` | Medium | 对话风格符合角色性格（启发式） |
| 6 | `worldline_adherence` | High | 内容不偏离主线大纲 |
| 7 | `choice_diversity` | Medium | 选项效果多样性 |
| 8 | `choice_validity` | High | 选项内容有效性 |

## 五、Pipeline 架构

```
输入 (场景描述 + 角色卡[含背景故事] + 世界线[含标注])
        │
        ▼
┌─ Stage 1: Context Assembly ─────┐
│  解析世界线节点、标注当前位置       │
│  注入 annotatedWorldline           │
└──────────────────────────────────┘
        │
        ▼
┌─ Stage 2: Narrative Anchoring ──┐
│  LLM 生成场景旁白                │
│  含完整角色卡（性格+风格+背景）     │
└──────────────────────────────────┘
        │
        ▼
┌─ Stage 3: Dialogue Generation ──┐
│  LLM 生成角色对话                │
│  中文情绪标签（平静/急切/果断...）  │
└──────────────────────────────────┘
        │
        ▼
┌─ Stage 4: Choice Branching ─────┐
│  LLM 生成 2-4 个玩家选项          │
│  标注世界线影响类型               │
└──────────────────────────────────┘
        │
        ▼
┌─ Stage 5: Validation Gate ──────┐
│  8 项自动校验                    │
│  JSON 解析重试 + 验证重试（各 3 次）│
└──────────────────────────────────┘
        │
        ▼
输出 (旁白 + 对话 + 选项 + 世界线状态)
```
